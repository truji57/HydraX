1. OBJETIVO Y REQUISITO CRÍTICO
Construir una aplicación de escritorio Windows (C# .NET 8 + WPF) que copie operaciones en 
tiempo real de una cuenta Master MT5 a múltiples cuentas Follower MT5, soportando entre 5 y 
20 followers simultáneos.
 REQUISITO CRÍTICO — NO NEGOCIABLE🔴
Las operaciones copiadas a los followers MT5 DEBEN aparecer como MANUALES en el 
historial
NO deben aparecer como operaciones de EA (Expert Advisor)
SOLUCIÓN: Conectarse a la terminal MT5 via Named Pipe interno o MT5 Manager API con 
magic=0
NUNCA usar un MQL5 EA para enviar órdenes al follower — eso las marcaría como EA
magic=0 + canal de terminal = MT5 las registra como orden manual del usuario

3. CÓMO LOGRAR ÓRDENES MANUALES EN MT5
3.1 Por qué funciona
Método de envío magic number Aparece en MT5 como
EA MQL5 (OrderSend) cualquiera ≠ 0 Expert Advisor
Script MQL5 cualquiera Script
Terminal API / Named Pipe con 
magic=00 Manual ✓
MT5 Manager API con magic=0 0 Manual ✓
3.2 Implementación — Named Pipe Connector
MT5 Desktop expone un named pipe por cada proceso abierto. Conectarse a él permite enviar 
órdenes como si fuera el propio usuario de la terminal:
// TradeCopier.MT5 / MT5PipeConnector.cs
public class MT5PipeConnector : IMT5Connector
{
    private NamedPipeClientStream _pipe;
    private int _pid;
    // 1. Buscar el proceso MT5 que tiene logueada la cuenta correcta
    public Process FindMT5Process(string accountLogin)
    {
        return Process.GetProcessesByName("terminal64")
            .FirstOrDefault(p => GetMT5Login(p.Id) == accountLogin);
    }
    // 2. Conectar al pipe del proceso
    public async Task ConnectAsync(int pid)
    {
        _pid = pid;
        _pipe = new NamedPipeClientStream(".",
                    $"MetaTrader5_{pid}", PipeDirection.InOut,
                    PipeOptions.Asynchronous);
--- PAGE 3 ---
        await _pipe.ConnectAsync(timeoutMs: 5000);
    }
    // 3. Enviar orden — magic=0 → MT5 la registra como MANUAL
    public async Task<bool> OpenTradeAsync(TradeRequest req)
    {
        var cmd = new MT5PipeCommand
        {
            Action   = MT5Action.OrderSend,
            Symbol   = req.Symbol,
            Type     = req.IsBuy ? OrderType.Buy : OrderType.Sell,
            Volume   = req.Lots,
            Magic    = 0,          // ← CRÍTICO
            Comment  = req.Comment ?? string.Empty,
            TP       = req.TakeProfit ?? 0,
            SL       = req.StopLoss ?? 0,
        };
        return await SendCommandAsync(cmd);
    }
}
  Si tienes acceso al MT5 Manager API (requiere ser broker o tener SDK), úsala en su lugar ⚠
— es más robusta. El Named Pipe es la alternativa para usuarios retail, que es lo que usa el 
MTM en su versión Lite.
4. MOTOR DE COPIA — CORE ENGINE
4.1 Flujo completo
1.Monitor polling cada 100ms detecta nueva posición abierta en Master
2.Validar: símbolo permitido, dentro ventana horaria, no más antigua de X horas
3.Para cada Follower activo y conectado:
   1.Calcular lot size según MM Mode configurado
   2.Resolver nombre de símbolo: aplicar prefix/suffix o Symbol Mapping
   3.Verificar slippage máximo si configurado
   4.Enviar orden con magic=0 via Named Pipe / Manager API
   5.Registrar en SQLite: ticket master, ticket follower, lots, símbolo, 
timestamp
   6.Emitir log con resultado (éxito/error) por follower
4.Cuando Master cierra posición → cerrar posición correspondiente en cada follower

5.4 Notas de implementación
  El campo *Symbol es obligatorio para los modos que necesitan calcular el valor del punto. ⚠
Si el símbolo no está disponible en el follower, mostrar warning.
  'Incl. Contract Size Calculation' es crítico cuando master opera en un broker con contract ⚠
size 100 y follower tiene contract size 1 — sin esto el lot quedaría 100x más grande o más 
pequeño.
  Los modos Risk % con 'Master's Stop-Loss' requieren que el master tenga SL definido en la⚠  
posición — si SL=0, usar fallback o no copiar con warning.
